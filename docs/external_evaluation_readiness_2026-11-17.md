No large dataset, project-page corpus, reserved labels, model or external code was downloaded/executed. No account signup, scraping, model training or publication occurred. This is a source/readiness assessment, not an external accuracy result.

**Recommendation:** investigate a narrow 2025–2026 Web Robots cohort first. Its recent header and location/category structure are now verified by a strictly bounded prefix read; use permissions, field semantics and snapshot alignment still need review. Do not score either source as-is. Kaggle `kemical/kickstarter-projects` can support a later-historical robustness study, but it cannot establish 2026 performance. A modern input passing the app validator is only a software test.

## Permissions and access

Web Robots advertises free/public dataset links, but no explicit dataset-specific reuse/redistribution license was found on the reviewed collector page. Its [service terms][WR-terms] discuss copyright responsibility and service ownership; they are not a clear dataset license. Confirm permitted research use, retention, redistribution and derived-artifact publication with the provider/advisor before collecting or committing data. Public availability is not proof of unrestricted use.

Kaggle's declared license requires reviewing attribution, noncommercial and share-alike obligations for the intended use. Do not assume a public demonstration or model/data redistribution automatically satisfies those terms. Store any approved external dataset locally and ignored; record the exact dataset version, files, checksums, acquisition date and license evidence.

The current [Kickstarter terms URL][KS-terms] redirects to a JavaScript legal portal. The directly readable [November 2022 terms][KS-2022] prohibit crawling/spidering; the currently governing terms should be checked before any new collection. This review does not authorize automated scraping or bypass access controls. Existing provider archives or consented creator exports are preferable research leads, not an exemption from source rights.

## Harmonizing the frozen five-input U.S. model

The frozen U.S. pipeline requires `goal`, positive fractional-day `duration`, `category`, `subcategory`, and a supported listed `City, ST`/state-DC location. It cannot be evaluated honestly by filling unavailable inputs with invented values. No new encoder fitting, tuning, model selection, threshold adjustment or calibration may use the external test outcomes.

| Input or outcome | Required audit before scoring |
|---|---|
| `goal` | Establish native units and the recorded configuration at prediction time. Prefer explicit USD records for the first U.S. pilot. Preserve the frozen input meaning; inflation adjustment or new conversion rules would be a separate, prespecified variant. The old source's unresolved semantics remain a limitation. Never use pledged totals as the goal. |
| `duration` | Use documented planned campaign length, potentially `(deadline - launched_at)/86400` only after verifying those fields' meanings and dates. Keep fractional days. Do not use elapsed time to successful funding, scrape time or delivery date. |
| Category/subcategory | Build an outcome-blind mapping between newer parent/subcategory labels and the historical taxonomy. Report unmapped/unseen coverage and fitted-fallback rates. Do not infer a mapping from which choice improves accuracy. |
| Listed location | Recover an actual supported state/DC or documented equivalent of the old listed-location proxy. Registration `country=US` is not the same field or population. A country-only dataset cannot be made valid by inventing a state or city. |
| Outcome | Use a sufficiently late snapshot with an explicitly settled `successful`/`failed` funding state. Exclude live projects; predefine treatment of canceled/suspended/unknown states. Funding success is not successful product delivery or fulfillment. |

Kickstarter's [funding-goal guidance][KS-goal] describes launch-time constraints, but its more specific [project-editing policy][KS-edit] records support-granted deadline extensions introduced in March 2020. Do not infer universal deadline immutability or equate a final deadline with the original planned duration across old/current cohorts. Goal stability, approved exceptions and field provenance must be checked by policy era. Neither guidance certifies a third-party scraper's mapping, the legacy `duration` definition, or immutability of location/category fields. Snapshot provenance still matters.

## Temporal design that avoids outcome leakage

1. **Prespecify one pilot population before opening outcome labels.** For example, USD campaigns with supported U.S. listed locations and launches in a fixed 2025 window, observed in a permitted early snapshot and a later settled snapshot. The exact window and coverage depend on the header/snapshot audit; do not claim it is already available.
2. **Keep one project identity across archives.** Use the stable project ID/URL, record all observation times, deduplicate cross-category rows within a scrape, and join snapshots by ID. Never place different monthly observations of the same campaign in separate training/test groups. Exclude overlap with all historical training/development/reserved project IDs using a protected ID-only manifest, without reading reserved targets.
3. **Separate inputs from labels in time.** Select features solely according to the declared prediction point; obtain labels only from a later observation after the funding deadline. The earliest monthly observation may occur weeks after launch, so it does not automatically validate pre-launch inputs. If launch snapshots cannot be established, label the result an early-campaign or post-snapshot historical check instead of a pre-launch evaluation.
4. **Do not use final updates, backers, comments, pledged, funded percentage, staff/funding badges, final edits, or other outcome/engagement fields as inputs.** Label extraction may use documented final funding state, but outcome columns must be physically separated from the prediction frame. Do not substitute planned activity for actual measured activity.
5. **Freeze model and protocol before scoring.** Verify v1's hash, validate the five columns, report dropped/missing/unseen cases and cohort coverage, then generate predictions once. Report accuracy, ROC-AUC, failure recall, confusion matrix, Brier/calibration and a majority baseline with support and project-level uncertainty. Model choice or error-driven modifications require a distinct future development cohort, not repeated tuning on this external cohort.

Random selection of old and new rows together is not a temporal test. The frozen model already embodies 2009–2012 development choices; a clean later cohort should remain external. A result on 2013–2017 projects describes that era, not present-day Kickstarter.

## Smallest useful next action

The bounded header/nested-key inspection is complete. Request/confirm the archive's permitted use, then perform a small, outcome-blind **field-semantics and cross-snapshot pilot**: native-USD goal interpretation, valid listed-state reconstruction, parent/subcategory mapping, planned duration, and feature observation times. Use known stable IDs only to pair early features with later labels after the protocol is fixed. Keep label values sealed during this initial audit. Record full file fingerprints only when an approved complete acquisition occurs; the bounded prefix is not a full-archive checksum.

Only after those checks pass should the team acquire the minimal necessary recent snapshots and score a frozen, prespecified population. This report provides a concrete candidate contract, not evidence that snapshot-time alignment or modern model accuracy is already verified.

If the required location or prediction-time snapshots are unavailable, stop short of an accuracy claim. The next option is consented creator-owned initial configurations plus later outcomes, or a separately scoped model/evaluation with a new input contract. Do not fabricate missing state values, silently redefine country as listed location, or replace initial values with final snapshots.

Modern examples entered into Streamlit now can test validation, runtime compatibility, probability consistency and out-of-support warnings. They cannot yield measured modern accuracy without known outcomes and suitable prediction-time inputs. Neither the new international/mixed models' omission of money nor the existence of recent archives removes that requirement.
